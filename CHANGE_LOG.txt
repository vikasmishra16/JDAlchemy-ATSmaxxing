PROJECT OVERVIEW
================================================================================

JDAlchemy is a local-first AI resume tailoring system.

INPUT:
  - A candidate's existing resume (JSON, PDF, or DOCX)
  - A job description (plain text)

OUTPUT:
  - A tailored resume with improved bullet phrasing
  - A rewrite diff showing before/after
  - A cover letter
  - A PDF (via LaTeX renderer)
  - Hallucination risk metrics
  - Resume strength scores

CORE PHILOSOPHY:
  "Grounded believable enhancement" — NOT "AI-generated resume sludge"

  The system rewrites bullet points to be clearer, more technical, and better
  aligned with the JD — while NEVER inventing tools, metrics, projects,
  companies, roles, dates, or certifications not already present in the resume.

  Target output tone: "A strong senior engineer editing their own resume on
  their best day."

  NOT: "A career coach template" or "AI buzzword machine."

KEY CONSTRAINTS:
  - Local-first (Ollama, runs on modest hardware)
  - Low RAM environment — small models (mistral:latest by default)
  - num_ctx: 2048, num_predict: 384, temperature: 0.2
  - No cloud APIs unless explicitly configured
  - No hallucination tolerance — grounding validation is enforced in code

================================================================================
ARCHITECTURE (VALIDATED — DO NOT REDESIGN)
================================================================================

1. Resume is parsed deterministically from file → schema (Pydantic)
2. JD is analyzed by LLM → structured JobDescription schema
3. Bullet groups are rewritten LOCALLY per section (experience, projects)
   - Each group rewritten in isolation
   - LLM only sees: the bullets for that section, context, JD JSON, mode
4. Rewritten bullets are injected back into the deterministic schema
5. Hallucination validation runs on the full before/after diff
6. Bullet optimizer post-processes (trim, capitalize, sentence-end)
7. Output: tailored JSON, PDF (LaTeX), cover letter, diff, metrics

WHAT WAS TRIED AND FAILED (do not re-attempt):
  - Full resume regeneration via LLM → hallucinations, fake projects,
    unstable JSON, excessive latency. ABANDONED.
  - Multi-agent orchestration → overengineered, not needed. REJECTED.
  - Chain-of-thought JSON objects ({"analysis":..., "bullet":...}) →
    considered, then EXPLICITLY REJECTED by project owner.
    The flat JSON array of strings is the correct and validated output format.
  - Large context workflows → incompatible with RAM/model constraints.

================================================================================
REWRITE PHILOSOPHY SUMMARY (v3)
================================================================================

TARGET TONE: "A strong senior engineer editing their own resume to a peer."

ALLOWED:
  - Replace weak verbs with precise implementation verbs
  - Restructure clause order for clarity
  - Remove filler and hedging words
  - Surface specifics already in bullet or section context
  - Vary sentence structure across bullets
  - Front-load strongest technical action

FORBIDDEN:
  - Inventing any tool, metric, project, company, role, date, certification
  - Adding "REST" if original just says "API" (unless REST is stated)
  - Business outcome claims not in original
  - Seniority inflation
  - Corporate buzzwords: leveraged, spearheaded, orchestrated, etc.
  - Motivational language: passionate, dynamic, results-driven, etc.
  - AI-sludge phrases: ensuring seamless, driving key, instrumental in, etc.

GROUNDING RULE (CRITICAL):
  Specificity upgrades allowed ONLY from:
    a) explicit text in the original bullet
    b) technologies listed in the structured context for that section
  NEVER from general domain knowledge or JD keywords.
